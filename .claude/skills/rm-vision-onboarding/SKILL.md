# RM 视觉自瞄 · 协作方式

## 用户背景（每次都要记住）

**电控转视觉。** 熟悉 STM32、C、串口调试、CAN、示波器、Keil。
不熟悉：OpenCV、卡尔曼滤波、PnP、四元数、相机成像原理、Linux 开发习惯。

这意味着：

- 他能看懂"寄存器""时序""独占访问"这类概念，不用解释
- 他不知道"曝光/增益/内参/畸变系数"分别是什么、谁管谁
- 他不知道 Linux 的 `/tmp` 会被清空、`DISPLAY` 是干什么的、`pgrep -f` 匹配的是什么
- 他不熟悉"一个 CMake 工程里有多个可执行文件"这种组织方式

**不要假设他知道任何视觉侧的常识。** 但也不要把他当新手程序员——嵌入式那套他很熟。

## 回答方式

### 1. 大白话优先

先用日常语言说清"这是什么、为什么"，再给术语。

不好：
> 曝光时间与增益共同决定传感器的信噪比，需在运动模糊与噪声之间权衡。

好：
> 曝光时间 = 快门开多久。开久了进光多、画面亮，但云台一转装甲板就拖成糊线。
> 增益 = 电子放大，等于把信号"调大声"，亮得快但噪点也跟着放大。
> 所以自瞄一般压曝光、适度加增益。

### 2. 给编号步骤，不给"你可以试试"

他明确说过"我不会步骤"。需要他动手时，写成第一步第二步，每步一条命令或一个动作。

```
第一步：坐到小电脑前面（窗口弹在它的屏幕上，Windows 这边看不见）
第二步：终端里粘这两行
        export DISPLAY=:0
        ./camera_tuning
第三步：看左上角 SHARP 那个数字，红色就是要调
```

不要写"你可以调一下曝光看看效果"——他不知道从哪调、调多少、怎么判断好了。

### 3. 做完要告诉他"现在什么状态"

每轮结束说清：改了哪些文件、验证了什么、哪些没验证、下一步该干什么。
他刚接手这套工程，需要靠这个建立地图。

### 4. 判断"合格"必须有依据

他会问"我调的合格吗"。**不能凭通用常识回答。** 必须先去代码和历史配置里找判据。

真实案例（务必引以为戒）：曾按摄影常识告诉他"亮度目标 100-130、过曝 <1%"，
让他白折腾了两轮。正确判据在 `tasks/auto_aim/detector.cpp` 的 `cv::threshold` 那行（当前第 64 行，
行号会漂，以函数名为准）：

```cpp
cv::threshold(gray_img, binary_img, threshold_, 255, cv::THRESH_BINARY);
```

检测器只看灰度 > `threshold`(150) 的像素。装甲板灯条自发光，压低曝光后
灯条仍亮而环境被压黑——**画面整体偏暗（亮度 40~60）才是目标状态**。
再看 `configs/demo.yaml` / `sb_long.yaml`，队里上车实际用的是
`exposure_us: 4000, gain: 0.4~0.5`，和"好看的亮度"差一个数量级。

**先 grep 代码 + 看历史配置，再下判断。**

## 这个工程的关键事实

### 相机

- 大恒 MER2-160-227U3C，USB `2ba2:4d55`，SN `FDN21050087`（`configs/calibration.yaml` 里另有 4 段注释掉的备用相机配置，别改错段）
- SDK 库 `/lib/libgxiapi.so` 已装；`libdximageproc` **没装**，要转 Bayer 用 OpenCV 的 `cvtColor`
- **独占访问**：同一时刻只能一个程序开着。冲突时报 `-0x3ec`（`GX_STATUS_INVALID_ACCESS`）
- 杀掉占用进程后**必须等内核回收 USB 句柄**，立刻重开照样报 `-0x3ec`
- 曝光只在 `io/daheng/daheng.cpp` 的 `initialize_camera` 里设一次，**运行期改不了**。所以调参工具直接调 SDK，绕过 `io::Camera`
- 上位机（GxViewer）改的是相机易失状态，`user_set_default = 0` 意味着断电就丢。**最终一定要落到 yaml**

### 参数存放

| 文件 | 作用 |
| --- | --- |
| `configs/calibration.yaml` | 唯一生效的地方。程序启动时读它去设相机 |
| `configs/tuning_result.yaml` | `camera_tuning` 按 `p` 存的结果，**程序不读**，供人工抄写。已在 `.gitignore` |
| `configs/demo.yaml`、`sb_long.yaml` | 跑离线视频用，含 detector 的 `threshold` 等参数 |

`calibration.yaml` 里有 5 段相机配置（4 段注释掉），还夹着标定矩阵和大量中文注释。
**不要让程序自动改这个文件**，容易改错位置且不易发现。

### 编译运行

- 一个 CMake 工程，10 个可执行文件（`add_executable` 见根 `CMakeLists.txt`）
- **必须先 `cd build` 再跑**：程序内部用 `../configs/xxx.yaml` 相对路径
- Alt+, 编译 / Alt+N 运行 / Alt+M 编译+运行，**跟着当前打开的文件走**（`scripts/build_current.sh`、`scripts/run_current.sh` 从 CMakeLists 现解析映射）
- 源文件增删或改了 CMakeLists 后要 `cmake -S . -B build` 重新配置，光 `make` 不够

### 小电脑（SSH 主机 `xiaodiannao`）

- 工程在 `~/RM27_zimiao/27zm_zy_20260826`
- GUI 程序需要 `export DISPLAY=:0`；GNOME 跑 Wayland，认证文件是 `/run/user/1000/.mutter-Xwaylandauth.*`
- 窗口弹在小电脑接的显示器上（DP-2），**SSH 这边看不到**
- `/tmp` 重启会被清空，工具和脚本要放进仓库

## 常见陷阱（都真实踩过）

**旧二进制配新配置。** `build/` 里的可执行文件可能是几天前编的。上游删了某个 yaml
字段而旧二进制还在读它 → `[YAML] xxx not found!` 直接退出。先重新编译再排查。

**`pgrep -f "build/xxx"` 匹配不到。** 程序是在 `build/` 里以 `./xxx` 启动的，
cmdline 就是 `./xxx`，不含 `build/`。要按 `/proc/<pid>/exe` 的真实指向比对绝对路径。

**配置里的相机 SN 不是实机那台。** 先用 SDK 枚举读出真实 SN 再改配置，别猜。

**PowerShell 往 SSH 传带引号的复杂命令会被转义搞坏。** 把脚本写到远端文件再执行
（注意剥掉 UTF-8 BOM，否则 bash 报 `﻿cd: 未找到命令`）。

**pull 前先看本地改动。** 他本地常有未提交的配置改动（`.clangd`、`tasks.json` 等），
用 `git pull --ff-only --autostash` 保住它们。
